# Deployment

## Backend — AWS CDK, Java (`cluelux-backend-java/`)

Two fully isolated stacks (`ClueLuxBackendStack` = prod, `ClueLuxBackendStackUAT` = UAT). Full resource detail in `backend.md`; this is the deploy sequence.

### Prerequisites
- AWS CLI configured (`aws configure`), credentials for account `211125414476`.
- Java 21 + Maven (`mvn -version` to confirm).
- Node.js (only for the CDK CLI itself — the stacks are Java, but `cdk` the command still runs on Node, installed under `cluelux-backend/node_modules`).

### Deploy sequence (recommended order: UAT first, always)
```bash
cd cluelux-backend-java
export CDK_DEFAULT_ACCOUNT=211125414476
export CDK_DEFAULT_REGION=us-east-1
export PREVIEW_KEY=<the key — not committed anywhere, ask for it>

# 1. Review UAT
npx --prefix ../cluelux-backend cdk diff ClueLuxBackendStackUAT

# 2. Deploy UAT, verify with real requests against its ApiUrl output
npx --prefix ../cluelux-backend cdk deploy ClueLuxBackendStackUAT

# 3. Only once UAT looks right — review prod
npx --prefix ../cluelux-backend cdk diff ClueLuxBackendStack

# 4. Deploy prod
npx --prefix ../cluelux-backend cdk deploy ClueLuxBackendStack
```

Always target stacks **by name**, never `cdk deploy --all` — that way a UAT-only change can never accidentally bundle a prod change into the same approval step.

### Build-once, promote (recommended practice, not yet automated)

`cdk.json`'s `app` command rebuilds the Lambda jar from source (`mvn package`) on every single `cdk synth`/`diff`/`deploy` call — so steps 2 and 4 above currently compile the jar twice, independently. If the source changes in between, UAT and prod can silently end up running different code despite "testing in UAT first." Until this is automated:
- Build once: `mvn -pl lambda package -DskipTests`.
- Don't touch the source between the UAT deploy and the prod deploy.
- Tag the commit after a successful prod deploy: `git tag -a v2026.11.01 -m "description" && git push --tags` (ask before pushing tags to a shared remote).

### Costs
DynamoDB on-demand, Lambda, and API Gateway all have generous AWS free tiers (DynamoDB 25GB+25 WCU/RCU, Lambda 1M requests + 400,000 GB-seconds/month, API Gateway 1M calls/month) — prod is expected to stay near **$0/month** at this traffic level. UAT roughly doubles the Lambda/API Gateway/DynamoDB line items but no CloudFront, so it's cheaper per-resource than prod, not more. CloudFront's own free tier (1TB egress + 10M requests/month, shared across every distribution in the account) covers prod's CDN at this scale too.

### Troubleshooting
- **Lambda errors**: `aws logs tail /aws/lambda/<function-name> --follow` — prod's function name is auto-generated by CDK (check the Lambda console or `cdk deploy` output); UAT's is explicitly `cluelux-get-daily-word-uat`.
- **API returns 500**: per `GetDailyWordHandler.java`, only happens on an actual thrown exception (e.g. DynamoDB permission error) — check CloudWatch logs and the `TABLE_NAME` env var on the function.
- **Prod stack shows unexpected changes in `cdk diff`**: stop and read the diff carefully before deploying — the whole point of having moved to this Java setup was verifying `cdk diff` shows *exactly* the expected changes, nothing more (see the resource-ID-matching rationale in `ClueLuxBackendStack.java`'s class comment).

### Workflow: develop → UAT → promote

1. Work on the `uat` branch. Push → Amplify auto-builds `uat`, live against the UAT *backend* within a couple minutes - a real shareable URL, not just a local dev server.
2. For a backend change alongside it: `cdk deploy ClueLuxBackendStackUAT` manually (CDK doesn't auto-deploy on push the way Amplify does).
3. Test against the `uat` branch URL until satisfied.
4. Promote: merge `uat` → `master` (triggers the prod Amplify build), then tag the commit: `git tag -a v2026.11.02 -m "description" && git push --tags`. For the backend, deploy the *same* already-built jar to prod rather than rebuilding - see "Build-once, promote" above.

## Loading daily word data (either backend stack)

No automatic seeding — load directly via AWS CLI:
```bash
aws dynamodb put-item --table-name ClueLuxWords --item file://item.json       # prod
aws dynamodb put-item --table-name ClueLuxWords-uat --item file://item.json   # UAT
```
See `content-and-hints.md` for word/hint content generation and QA before anything is loaded.
